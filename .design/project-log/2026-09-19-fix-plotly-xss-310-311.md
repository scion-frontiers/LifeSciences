# Fix: Plotly XSS in docking-scores-viewer and admet-viewer (#310, #311)

**Date:** 2026-09-19
**Author:** mantis2-plotly-em
**Issues:** #310, #311
**Branch:** scion/mantis2-plotly-em

## Summary

Fixed two XSS vulnerabilities where user-controlled data flows unescaped into
Plotly chart fields. These are the same vulnerability class as #303-#305 and #309,
using the proven escapeHtml pattern from commit 4a79784.

## Changes

### #310 — docking-scores-viewer.html
- **Vulnerability:** Pose labels (`pose_id`, `id`, `mode`) from JSON data flow
  unescaped into Plotly x-axis tick labels. Plotly parses pseudo-HTML in string
  fields, enabling XSS via `<a href="javascript:...">` injection.
- **Fix:** Added `escapeHtml()` function and wrapped the pose label extraction
  with it: `escapeHtml(p.pose_id || p.id || p.mode || ('Pose ' + (i + 1)))`.

### #311 — admet-viewer.html (renderGeneric)
- **Vulnerability:** Property names (`e.property`, `e.name`, `e.endpoint`) flow
  unescaped into Plotly x-axis labels (bar chart) and polar theta labels (radar
  chart) in the `renderGeneric` fallback path. The file already had `escapeHtml`
  but it was not applied to these values.
- **Fix:** Applied existing `escapeHtml()` to the names array:
  `escapeHtml(e.property || e.name || e.endpoint || '')`.

## Tests

Added 5 targeted tests to `applications/DDE/tests/test_xss_escape.js`:
- 3 tests for docking-scores-viewer (#310): escapeHtml presence, usage on pose
  labels, absence of unsafe pattern
- 2 tests for admet-viewer (#311): escapeHtml usage on property names in
  renderGeneric, absence of unsafe pattern

Also added `docking-scores-viewer.html` to the VIEWER_FILES integrity check array.

All 77 tests pass (previously 69).
