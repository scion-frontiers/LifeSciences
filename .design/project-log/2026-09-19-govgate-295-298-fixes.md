# Fix: Governance Gate Bypass Vulnerabilities #295 and #298

**Date:** 2026-09-19
**Branch:** `dev-program-295-298`
**Files changed:**
- `applications/DDE/tools/dde/commands/program.py`
- `applications/DDE/tests/test_program_govgate_295_298.py` (new)

## Issue #295: Missing duplicate/collision detection in batch program registration

**Problem:** Step 1c guarded against WO ID overlap between JSON and markdown formats, but failed to validate unique IDs *within* markdown files. When multiple markdown files defined the same WO ID (e.g., `WO-001`), both were ingested silently. Step 4's `_conflict_exists()` only checked against existing records on disk, not within the import batch.

**Fix:**
1. **Step 1c-ii:** After the cross-format overlap check, added intra-markdown uniqueness validation. If `len(md_records)` differs from `len(set of md IDs)`, the duplicate IDs are identified and a `Refusal` is raised.
2. **Step 4a:** Before checking conflicts against disk, added a duplicate `(record_type, ident)` check within the `all_imports` batch. This prevents two records with the same identifier from being silently written (one overwriting the other).

## Issue #298: Incomplete Step 5 pre-validation permits partial writes

**Problem:** Step 5 pre-validated records via `controlstore._VALIDATORS` but omitted two checks that `write_record` (step 6) enforces: identifier format validation against `_SAFE_IDENTIFIER_RE`, and JSON serializability. When step 6 failed mid-loop on these checks, preceding records were already written, and subsequent resume runs failed with `Refusal` from `_conflict_exists()`, locking the project.

**Fix:**
1. **Step 5a:** Added identifier validation against `_SAFE_IDENTIFIER_RE` (imported from controlstore). Invalid identifiers (containing dots, spaces, etc.) are now caught before any writes.
2. **Step 5b:** Added `json.dumps(data)` test for each record. Non-serializable types (e.g., `datetime.date` from YAML `safe_load`) are caught before any writes.
3. **`_build_markdown_record`:** Cast `stage` and `cycle` to `str()` to prevent `yaml.safe_load` from producing `datetime.date` objects that would fail JSON serialization downstream.
