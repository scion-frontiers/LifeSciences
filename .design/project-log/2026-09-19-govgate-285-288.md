## Issue #285: Non-dict truthy value bypasses liability justification validation

**Location:** `_perform_commit()` around line 490–513

**Bug:** When active Critical liabilities exist, the code required a
`liability_justification` field. The `if not justification:` guard caught
None/False/empty, but any truthy non-dict value (string `'bypass'`, int `1`,
bool `True`) passed. The subsequent `if isinstance(justification, dict):` had
no `else` branch, so non-dict truthy values skipped the unjustified-liabilities
check entirely.

**Fix:** Changed `if isinstance(justification, dict):` to
`if not isinstance(justification, dict): raise SchemaError(...)`. Also added
per-value validation ensuring each justification entry is a non-empty,
non-whitespace string.

## Issue #288: Key naming mismatch in override path-confinement check

**Location:** `override_cmd()` around line 949–971

**Bug:** The path-confinement enforcement only inspected
`detail.get("path_confinement_failures")`. But `_check_analysis_citations`
stores path-escape errors under `detail["issues"]`. So path-confinement
violations in analysis citations could be overridden.

**Fix:** Added a secondary check that inspects `detail["issues"]` for entries
containing "escapes project root" (case-insensitive). If found, raises
`Refusal` with the same path-confinement message.
